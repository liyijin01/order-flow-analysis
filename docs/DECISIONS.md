# 关键决定（不要随意改）

改动下面任何一条，必须在任务文档里明确写出，并同步更新本文件。

## 1. 价位和区域的定义

| 名称 | 定义 | 验证依据 |
|---|---|---|
| 季度 VAH / VAL（`Q1 VAH`、`PQ VAL`、`PY Q4 VAL` 等） | 该季度 1h K 线、从季度起点锚定的 VWAP（hlc3，成交量加权），季度结束时的 VWAP ±1σ（成交量加权总体标准差） | `scripts/c4_1_golden.py`：ETH 2026Q2 = (2008.09, 2295.37, 1720.81) 等 6 组，误差 ≤ 0.05% |
| PQ 上季价值区 | 同上，取上一季度 | 同上 |
| PM 上月价值区 | 上月 30m K 线的 TPO 70% 价值区，每行 100 个 tick，单行扩展 | D1 月度探针：ETH 2025-11 VAL = 2707.00，参考值 2705.89，误差 0.04% |
| 去年月份价位（`PY Nov VAL` 等） | 同 PM 的 TPO 算法，取去年各月 | 同上 |
| PW 上周价值区 | aggTrades 精确成交量分布 70%；精确数据过期或缺失时，才用 30m TPO 兜底（标 ≈） | |
| 价值区算法 | JS 统一由 `web/shared/value-area.js` 提供**单行扩展**；`engine.js` / `indicators.js` 调用共享实现，Python `pipeline/tpo.py` 同口径 | D16 金标准 + D19 一周 30m / 月线 fixture 的 JS / Python rows、POC、VAH、VAL 完全一致 |

## 2. 数据和 CI

- GitHub 美国 runner 访问 Binance API 返回 451。CI、快照、每日 PNG 只用 data.binance.vision；浏览器实时页面直接请求 Binance API。
- data.binance.vision 发布时间：日度 aggTrades 约次日 07:00~07:31 UTC，日度 K 线约次日 07:50~08:35 UTC，月度文件约次月 2 日。下载 404 时 `load_day` 静默返回空，**任何使用归档的计算都必须先检查数据是否完整**。
- 每日定时任务 09:25 UTC。快照的截止时间按实际拿到的数据如实写，落后超过 2 天就失败。
- USD-M 周线归档只到 2024-01，周线一律由日线聚合（周一 00:00 UTC 起）。
- bookDepth 档位为 ±0.2 / 1 / 2 / 3 / 4 / 5（没有 2.5）。2026-09-07 ~ 09-11 的归档有异常，按日隔离、不插值。
- 关键价位缓存在 data 分支 `levels/`，只缓存 `complete: true` 的周期；深度采样缓存在 `depth15m/`；日度价格阶梯在 `ladders/`。
- 能本地运行时，push 前先跑单元测试和浏览器回归；不能本地运行时，每完成一项就 push，以 CI 为准。
- **重构类 PR 必须 `model-diff` 零差异才能合并**；D19 的标准报告为 `0 differences across 30 cases`。

## 4. 滚动 / 年度 VWAP（D13）

- 滚动 VWAP：固定用 4h K 线、hlc3、成交量加权；窗口条件为 `t_i − windowSec < t_j ≤ t_i`。历史不足完整 30D / 60D / 90D / 365D 窗口时不输出该点；用前缀和 + 时间双指针实现。
- 年度 VWAP / VAH / VAL：完整 UTC 自然年，4h K 线，hlc3、成交量加权 VWAP；σ 为成交量加权总体标准差，VAH = VWAP + 1σ、VAL = VWAP − 1σ，取年末最终值。D13 金标准已通过：BTC 2024 VWAP = 64,976.4259，对参考 64,960.2 误差 +0.025%；BTC 2025 VAL = 87,286.0392，对参考约 87,280 误差 +0.0069%。

## 5. 周度 VWAP / 上周投影 / 年开盘价（D14）

- 周度 VWAP：固定用 30m K 线，UTC 周一 00:00 重置；hlc3、成交量加权，σ 为成交量加权总体标准差。
- 上周投影：上一周最终 VWAP / ±1σ 投影到下一周；上一周必须有最后一根 30m K 线，且缺口不超过 0.5%，否则不画。
- 年开盘价 Y O：当前 UTC 自然年 1 月 1 日 00:00 UTC 的 1d K 线 open。
- D14 金标准已通过（BTC，Binance Vision）：
  - 2026-09-21 周最终 VWAP = 84,703.2482，对参考 84,703.2 误差 +0.000057%；
  - 上周最终 +1σ / −1σ = 85,933.0793 / 83,473.4170，对参考 85,933.1 / 83,473.4 误差 −0.000024% / +0.000020%；
  - 2026-09-28 周截至 2026-10-01 05:00 K 线 VWAP = 83,725.8649，对参考 83,726.2 误差 −0.000400%；
  - 同时刻 +1σ / −1σ = 84,339.2983 / 83,112.4316，对参考 84,339.6 / 83,112.8 误差 −0.000358% / −0.000443%；
  - Y O = 87,608.3，对参考 87,610.2 误差 −0.00217%。UTC 1 月 1 日定义通过，无需改用 UTC+8 备选。

## 6. 月线 S/R / imbalance（D15，近似算法）

- 月线 S/R **是近似算法**：严格三月转折，右侧一根月线必须已收盘；之后只用已收盘月线的 close 判断是否突破。现价上下各只保留最近一条：被突破的转折点标 `S/R`，未被突破的转折高/低点标月份。
- D15 BTC USD-M fixture 对照：上方选中 2026-01 高点 97,932.1，对现货参考 97,924.49 误差 +0.0078%；下方选中 2026-05 高点 82,828.7，对参考 82,850.0 误差 −0.0257%，9 月收盘突破后标 `S/R`。
- 月线 imbalance **是近似算法**：连续三根月线满足 `c3.low > c1.high` 或 `c3.high < c1.low`；c1/c2 必须收盘，c3 可形成中；后续月线进入区域后只保留尚未触碰部分，完全穿过即删除。
- D15 BTC USD-M fixture 对照：选中 2026-08 → 2026-10 看涨 imbalance 81,500.0 ~ 83,136.6；对现货参考 81,478.87 / 83,410.39 的误差分别 +0.0259% / −0.3282%。他的图把上沿截到 S/R 82,850，我们按算法保留 c3.low，因此差异是预期的。

## 7. 月度 TPO 剖面（D16）

- 月度 TPO 剖面：30m K 线，70% 价值区，100 ticks/row，单行扩展；定义行与 PM / 去年月份价位完全同口径。只把 `complete: true` 的完整自然月缓存到 data 分支，当前月由前端 30m K 线现算。
- 未回补规则：对已结束月份的 VAH / VAL / POC，只用后续**已结束月份**的 `[low, high]` 判断触碰；第一次触碰就把延伸线截到该月 start。正在形成的月份不参与触碰判断。
- 价值区方框：当前 12 个月窗口内，在“价值区包含现价”的已结束月份里选择离现在最近的一期，从该月 start 延伸到右边缘。
- D16 BTCUSDT 金标准：2025-11 VAH = 102,030（参考 102,048，误差 −0.0176%）；2026-05 VAH = 81,230（参考 81,200，误差 +0.0369%）；2026-05 VAL = 76,350（参考 76,376，误差 −0.0340%），三项通过 ±0.15%。2026-08 VAH = 81,510，对参考 77,984 误差 +4.521%，未通过；按任务要求保留既有 TPO 定义，不为贴参考值改算法。

## 8. 周度 TPO 剖面 / 参考周 / single print（D17）

- 周度 TPO 剖面：UTC 周一 00:00 到下周一 00:00，30m K 线、70% 价值区、100 ticks/row、单行扩展。它和“综合”模板 PW 不同：综合 PW 优先使用 aggTrades 精确成交量分布，wprofile 固定使用 30m TPO。
- 参考周方框：在已结束的最近 52 周中排除最近 4 周，筛选 `[low, high]` 包含现价的周，自动取 `(high-low)/low` 最大者；配置可用周一日期手动覆盖。
- single print：定义行中 TPO=1 的连续区间，排除剖面上下两端尾巴；预计算至少 3 个定义行，展示时再要求高度 ≥ `max(3*rowSize, currentPrice*0.15%)`。只用后续已结束周期的 `[low,high]` 回补，部分触碰会切掉被碰到部分，剩余区间继续画；每个模板最多保留离现价最近的 6 段。
- D17 对照采用 BTCUSDT USD-M 30m TPO；任务中的 88,000 / 77,300 nPOC、83,500 当前周 POC、Jan W4 82,060~90,560 和月度 single-print 数值只作为人工图对照，不改变上述定义。

## 11. D19b 模板 / 图层架构约定（2026-10-09）

- **新模板和新图层必须通过 `needs(ctx)` 或模板 `history` 显式声明自己需要的数据**。实时 K 线请求是当前显示周期、当前模板及启用图层所需周期的并集；关闭的图层不得触发无关的历史数据请求。
- **`web/analysis/main.js` 不写任何模板 ID**。模板自己的信息行、manifest 值、历史数据需求和行为由 `web/analysis/templates/` 声明；公共计算由 `web/analysis/layers/` 提供。
- 纯重构遵守 37-case 完整哈希、页面外观、manifest 和快照检查；`model-diff` 的 Binance requests 单独比较，`calcLastClosedUtc` 允许逐项披露的变化，其他模型字段必须保持零差异。

## 12. D20 稳定币占比（2026-10-10）

- **数据源**：CoinGecko Demo API 的 `/coins/markets` 和 `/coins/{id}/market_chart`，只按美元市值计算。服务端 GitHub Actions 使用 `COINGECKO_DEMO_API_KEY` secret，密钥不写入网页或缓存。Demo 每天最多取近 365 天历史，使用官方自动日度粒度；空密钥或 API 报错时维持原缓存，数据 job 不失败。
- **分子**：Tether (`tether`)、USDC (`usd-coin`)、DAI (`dai`) 美元市值求和。
- **分母**：按 CoinGecko 当前市值排序，从币种中排除 `wrapped-tokens` 和 `liquid-staking-tokens` 两类后取 125 个。月初更新这 125 个 ID 并固定用于当月日更；当前点统一归入当天 00:00 UTC，另存真实 `fetchedAt`；回填缺币按 0 计且记录 `missingCoins`。这个分母与 TradingView CRYPTOCAP `TOTAL` 前 125 的成分可能不同，因此未校准的 `raw` 值不能直接宣称是 TradingView 官方占比。
- **单点校准**：用参考图 2026-10-05 前一日收盘 9.118%，`ratio = raw(2026-10-05) / 9.118`，图上展示 `raw / ratio`。校准点缺失时不伪造比例；`|ratio-1|>5%` 输出 warning。它只能匹配这个锚点，无法校正其余历史时刻分母构成差异。
- **手动关键位来源**：九条线全来自 KBeast 2026-10-05 的 `USDT.D+USDC.D+DAI.D` TradingView 截图，配置内逐条保留 `source: "manual · KBeast 2026-10-05"`，在 `latest.json` 中也声明来源。价位依次为 13.719、12.829、11.886、10.490、9.642、9.064、8.372、5.114、2.463%，自动数据不用于反推或改写这些历史关键位。
- **非 K 线入口**：模板使用 `dataSource: "macro/ssd"`，普通 SSD 不向 Binance 发 K 线请求；仅带 `overlay=btc` 时按需加载一组 BTCUSDT 1d 收盘价，叠加倒置左价格轴。
