# D8：深度数据在 CI 里预采样（19MB → 约 200KB）

仓库：https://github.com/liyijin01/order-flow-analysis
基线：**D7 合并后的 main**。D7 没合并前不要开始。
分支：`d8-depth-sampling`
范围：只改深度数据的存储和传输格式。深度的校验规则、分档、as-of 采样规则、页面显示都**不变**。

## 0. 执行规则（必须遵守）

1. 从最新 main 切分支。按 §2 顺序实现，每完成一步本地跑 `node --test web/tests/*.test.mjs` 和 `python -m unittest discover pipeline/tests -v`，通过后 commit。
2. **全部完成、本地测试通过后一次性 push**，然后等 CI 跑完。只有 CI 失败时才修复并再 push 一次。不要连续 push：每次 push 都会取消正在跑的 CI。
3. CI 全绿后**直接 squash merge 到 main，不需要等 review**。merge 后等部署成功，按 §3 自查，按 §4 回复。
4. 对话中途断开时，新对话里说“继续 D8，分支 d8-depth-sampling，看 git log 做到了哪一步”。

## 1. 问题

- `flow/data/depth-{SYMBOL}.json` 存了 21 天的全部原始快照：每个币种 60,480 条（每 30 秒一条），每条带 ±0.2 / 1 / 2 / 3 / 4 / 5 六个档位的 bid 和 ask。按相同格式实测每个文件约 18.7MB。
- 浏览器以 `cache:'no-store'` 加载这个文件，打开页面、切换币种、每 30 分钟全量重载时都会重新下载。手机上尤其慢。
- data 分支的 `depth/{SYMBOL}/{date}.json.gz` 每天每个币种约 350KB（gzip 后），3 个币种一年约 380MB，并且每次 workflow 都要 `git fetch origin data`。
- 页面实际只用到：每根 15m bar 收盘时刻的一个 as-of 快照，并且只用 1 / 2 / 5 三档。

## 2. 修复规格

### 2.1 构建阶段预采样（`pipeline/depth.py`，`scripts/d6_build_flow_snapshot.py`）

- 校验逻辑（缺档、重复、倒序、非单调、均价偏离、按日隔离）和统计口径**完全不变**。
- 对通过校验的快照，按当天 96 根 15m bar 的收盘时刻做 as-of 采样，规则和现有 `asof_sample` 一致：取收盘时刻及之前的最后一个快照，最多容忍 1 个 15m bar，超出就留空。
- 每条采样只保留 `depthLevels`（1 / 2 / 5）的 bid 和 ask 累计名义额，取整到 1 USDT，再加上所用快照的时间。

### 2.2 data 分支格式

- 新目录 `depth15m/{SYMBOL}/{YYYY-MM-DD}.json.gz`，内容为当天的校验统计（`totalSnapshots`、`rejected`、`reasons`、`rejectedSamples`、是否被隔离）加上 96 条采样。
- 构建时只读写 `depth15m/`。在 `pages.yml` data job 的“persist to data branch”步骤里加一行：如果 `datarepo/depth` 存在就 `git rm -r --quiet depth`，只删这一个目录，`ladders/` 不动。merge 后 main 第一次运行时会执行这一步。原始 zip 随时可以从 Binance Vision 重新下载，不需要保留原始快照。
- 已经隔离的日期（例如 2026-09-07 到 09-11）照样按日记录为隔离、没有采样，不插值、不补数。

### 2.3 页面数据（`flow/data/depth-{SYMBOL}.json`，`web/flow/*`）

- 文件改为 21 天 × 96 = 2,016 条采样，加上现有 manifest 字段（`bucketsUsed`、`snapshotsUsed`、`snapshotsRejected`、`invalidDays`、`missingDays` 等，数值口径不变）。
- 15m 显示按时间直接取采样；30m 显示取该 30m bar 收盘时刻对应的那条 15m 采样（即它的第二根 15m bar）。不插值，不产生额外时间槽。
- bucket 差分 `cum(b) − cum(a)` 仍在前端计算，结果必须和改动前逐 bar 完全一致。
- 去掉深度文件请求上的 `cache:'no-store'`，改为在 URL 上加 `?v={generatedAt}`，这样一天之内切换币种不会重复下载。

### 2.4 测试

- Python：每天采样 96 条；只保留 1 / 2 / 5 档；取整；超出容忍窗口的留空；被隔离的日期没有采样；30m 取值等于对应 15m 收盘采样。
- 一致性：用同一份原始快照 fixture，新方式算出的每根 bar 三档 bid / ask / delta，与改动前的 `asof_sample` + `bucket_diff` 结果完全相同。
- `d6_flow_png.cjs` 断言每个 `depth-*.json` < 300KB。
- D6 已有的 smoke 断言全部保留。

## 3. 验收

- PR 的 `test`、`flow-smoke`、`analysis-smoke`、`chart-smoke` 全绿。
- merge 后：线上三个 `depth-*.json` 每个 < 300KB；`flow.html` 的深度窗格和 PNG 与改动前看起来一致；data 分支里 `depth/` 已删除，只有 `depth15m/` 和 `ladders/`。
