## 1. 背景

他的月报是 4 张图加一段结论；我们现在每天出 31 张 PNG，但没有结论。他的结论其实是几类判断拼起来的：

- **价位重合**：例如“去年 11 月价值区的 VAL 和 5 月 VAH 重合”，就是不同方法得到的价位落在同一个价格附近；
- **位置状态**：例如“突破 365 天滚动 VWAP 和 2024 VAH 是看涨”、“周线守在 1 月第 4 周区间之上”、稳定币占比在 9.064% 之上还是之下。

简报页把这两类判断自动列出来，一个币一页，不生成文字观点。

## 2. 实现规格

### D21-1 模板输出简报数据

每个模板文件加两个函数（都只读现有模型，不重新计算）：

1. `briefLevels(ctx)`：返回这个模板画出来的价位，统一格式 `{price, name, template, kind}`：
   - `kind` 是 `line`（VAH / VAL / POC / VWAP / S/R / 年开盘价等水平线）或 `edge`（区域的上沿 / 下沿：imbalance、价值区方框、参考周区间、上周投影、single print）；
   - `name` 用图上的标签，例如 `PQ VAH`、`365D RVWAP`、`Jan VAH`、`imbalance 下沿`；
   - 曲线（季度 VWAP、滚动 VWAP、周 VWAP 及 ±1σ）取最后一根 K 线的值。
2. `briefStates(ctx)`：返回这个模板的位置判断，格式 `{name, value, reference, state, distancePct, template}`。`state` 只能是 `above`、`below`、`inside` 三个值之一。至少包括：

| 模板 | 状态 |
|---|---|
| `quarter` | 现价 vs 本季 VWAP；vs 上季价值区（PQ VAL ~ PQ VAH） |
| `rvwap` | 现价 vs 365D RVWAP、vs 今年 VWAP、vs 离现价最近的往年 VAH 或 VAL |
| `weekly` | 现价 vs 本周 VWAP；vs 上周价值区；vs 年开盘价 `Y O` |
| `monthly` | 现价 vs 上方线、下方线；是否在 imbalance 区内 |
| `mprofile` | 是否在价值区方框内（例如 `PY Nov VA`）；vs 当前月 POC |
| `wprofile` | 是否在参考周区间内；vs 当前周 POC |
| `ssd` | 稳定币占比 vs 9.064%；5 天变化（百分点） |

`combined` 不输出（它是旧版合集，内容和其他模板重复）。

### D21-2 生成简报数据

- 每日 PNG 生成时（同一个浏览器会话，快照模式），对每个币依次打开 6 个价格模板，取 `briefLevels` 和 `briefStates`，再取一次 `ssd` 的状态，写出 `analysis/brief/{SYMBOL}.json`：`{generatedAt, dataCutoffUtc, symbol, currentPrice, zones, levels, states, pngs}`。
- **合流区（zones）**：
  1. 只取现价上下 15% 以内的价位，按价格排序；
  2. 相邻两个价位相差不超过现价的 0.5%，就并成一个区（连续合并）；
  3. 每个区记录 `[low, high]`、包含的价位清单、**来自几个不同的模板**（`sources`）；
  4. `sources ≥ 3` 的区标为 `strong`，`= 2` 的标为 `medium`，只有 1 个来源的单独价位也保留（标 `single`），页面上默认折叠。
- `pngs`：这个币当天的 7 张 PNG 文件名（6 个价格模板 + `SSD-1d.png`），从 `latest.json` 取。
- `status.json` 加 `briefGeneratedAt`。

### D21-3 页面 `brief.html`

纯静态页，只读 `analysis/brief/{SYMBOL}.json`，**不请求 Binance**。结构从上到下：

1. **标题行**：`BTCUSDT.P 每日简报 · 数据截至 {JST}`，币种切换 BTC / ETH / SOL，过期提示沿用 D18。
2. **一句话概要**（按模板句式生成，不做观点判断）：`现价 {price}。上方最近的合流区 {low}~{high}（{n} 个来源），下方最近的合流区 {low}~{high}（{n} 个来源）。稳定币占比 {value}，在 9.064% {之上/之下}。`
3. **合流价位梯**：纵向价格梯，上方压力在上、下方支撑在下，中间一行是现价。每个区一行：价格范围、距现价 %、来源清单（例如 `PQ VAH · PY Nov VAL · imbalance 下沿`）、强度标记（`strong` 深色底、`medium` 浅色底）。每个来源都链接到对应模板的实时页面（`analysis.html?tpl=…&symbol=…`）。
4. **状态表**：D21-1 的所有状态，每行显示名称、当前值、参考值、状态（`上方 / 下方 / 区间内`，用颜色区分）、距离 %、模板链接。
5. **当天图表**：7 张 PNG 网格，点开看大图，每张下面附实时页面链接。

样式沿用分析板的深色主题；手机宽度下合流价位梯和状态表改成单列，PNG 网格改成一列。

`index.html` 在分析板入口旁边加 `每日简报` 入口。

### D21-4 测试和一处小修

- 单元测试：合流区合并（0.5% 连续合并、跨模板计数、15% 范围过滤）；状态判定（`above` / `below` / `inside` 的边界）。
- `scripts/smoke/brief.cjs`：用 fixture 打开 `brief.html`：没有 Binance 请求；三个币都能切换；`strong` 区排在正确位置；每个来源链接指向正确的模板和币种；手机宽度下没有横向滚动。
- 每日构建检查：三个 `brief/*.json` 都生成，`zones` 和 `states` 不为空，`pngs` 指向的文件都存在。
- **小修**：我在用户电脑上实测时，浏览器面板处于后台的那次，状态栏显示 `计算绘制 25.7s`；同一个页面在前台刷新只要 25ms。原因是后台标签页会暂停绘制，计时把等待绘制的时间也算进去了。把这一段拆成 `计算` 和 `绘制`；页面处于后台（`document.hidden`）时，绘制写成 `后台暂停`，不计入总耗时。
