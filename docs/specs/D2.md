## 2. 修复规格

### D2-1 VWAP 对齐到展示周期（`web/analysis/engine.js`，`web/analysis/main.js`）

- `engine.js` 新增 `alignSeriesToBars(points, bars, intervalSec)`：双指针 O(n)。对每根展示 K 线，取 `time < bar.time + intervalSec` 的最后一个 VWAP 点作为这根 K 线收盘时的值；在第一个 VWAP 点之前的 K 线不输出。输出的 `time` 必须等于这根 K 线的 `time`。
- `main.js` 的 VWAP 线只用对齐后的数据。**规则：任何序列都不能向时间轴引入展示 K 线以外的时间点。**
- 单测：4h 展示 + 1h VWAP，输出点数 ≤ 展示 K 线数，且每个输出 time 都在展示 K 线 time 集合里；每点的值等于该 4h 收盘时刻的累计 VWAP。

### D2-2 快照周线改为由日线聚合（`scripts/d1_build_snapshot.py`）

- 不再从 Binance Vision 下载 `1w`。改为加载 `1d`（从 `max(币种上线日, cutoff - 420 周)` 到 cutoff），用新函数 `aggregate_weekly(daily_bars)` 聚合：
  - 以周一 00:00 UTC 为周起点（和 Binance 周线一致）；
  - open 取第一根，high 取最大，low 取最小，close 取最后一根，volume、taker_buy_base 求和；
  - 只保留 7 根日线齐全、且 `周起点 + 7 天 <= cutoff` 的完整周。
- `1d` 序列直接复用同一批日线，取最后 430 天。
- `pipeline/tests` 或新建 `scripts/tests` 加 Python 单测：周一锚定、不完整周被丢弃、成交量和主动买量求和正确。

### D2-3 快照时间、截止日期如实、PW 过期兜底

1. `pages.yml` 定时改为 `'25 9 * * *'`（09:25 UTC，日本时间 18:25），留出 K 线日档 08:35 左右发布的余量。
2. `d1_build_snapshot.py` 截止日期如实：
   - 目标 cutoff 仍为当天 00:00 UTC；
   - 对每个币种 × 周期计算“最后一根完整 K 线的收盘时间”，取所有序列的最小值并向下取整到 UTC 日，作为实际 cutoff；
   - 实际 cutoff 早于目标时打印 `::warning::`，并把所有序列统一裁到实际 cutoff；
   - 落后超过 2 天直接 `exit 2`，不发布过期 PNG；
   - `cutoffUtc` 写实际值，PNG 页脚随之正确。
3. PW 兜底（`main.js`）：
   - 计算应有的上周起点 `pwStart = utcWeekStart(last.time) - 7 天`；
   - 若 `profiles.previous.expectedDays[0]` 不等于 `pwStart` 对应日期（文件过期），或 `complete=false`，视为精确数据不可用；
   - 此时用 30m TPO 计算上周价值区作为兜底，标签 `上周价值区 PW ≈`，周期 `W / 30m TPO`，来源 `approx`；
   - nPOC W 同样走这个判断（目前只在 `!pw` 时兜底，过期文件不会触发）。
   - 单测：给一个错一周的 profile，必须走 TPO 兜底。

### D2-4 供需区只用已收盘 K 线（`data.js`，`main.js`，`engine.js`）

- `data.js` 新增 `closedBars(bars, asOfMs)`：保留 `closeTime < asOfMs` 的 K 线。实时模式 `asOfMs = Date.now()`；快照模式 `asOfMs = Date.parse(cutoffUtc) + 1000`。
- 形成供需区（冲击段 + 基底）和失效判断（收盘越过远端边界）**只用已收盘 K 线**。
- “已测试”可以额外参考未收盘 K 线的 high / low（触碰一旦发生就不会撤回），但它不能让区域失效。
- 单测：已收盘 K 线相同、只改变最后一根未收盘 K 线的 OHLC，`detectZones` 输出必须完全一致；未收盘 K 线收在远端边界之外时区域仍然有效。

### D2-5 价格所在区域必须显示（`engine.js` 的 `selectZones`，`main.js`）

对每个合并后的有效区域计算状态和距离：

| 状态 | 条件 | 距离 |
|---|---|---|
| `inside` 测试中 | `bottom <= price <= top` | 0 |
| `ahead` 正常 | 供应区在上方（`bottom > price`）或需求区在下方（`top < price`） | 到近端边界 |
| `breaking` 击穿待确认 | 未收盘价格已越过远端，但还没有收盘确认 | 到远端边界 |

- 距离 ≤ `maxDistancePct` 的纳入。
- 排序：`inside` 优先，然后按距离，再按强度。
- 每侧仍最多 `perSide` 个。
- 标签和表格状态追加 `·测试中` 或 `·击穿待确认`。
- 单测覆盖三种状态，供应区、需求区各一组。

### D2-6 刷新不复位视图（`main.js`）

- `state.viewKey = symbol + '|' + timeframe`。只有首次加载或切换币种 / 周期时设置默认视图（见 D2-7）。
- 其他刷新时：`setData` 前记录 `getVisibleLogicalRange()`，`setData` 后恢复。
- 如果用户原本就停在最右侧（`range.to >= 原K线数 - 1`），则按新增 K 线数整体右移，继续跟随最新价。
- 删除所有 `fitContent()` 调用。

### D2-7 默认视窗（`config/analysis-rules.json`，`main.js`）

- 新增 `display.visibleBars: {"4h": 180, "1h": 240, "1d": 180}`。
- 默认视图为 `setVisibleLogicalRange({from: n - visibleBars, to: n - 1 + rightOffset})`。
- 已加载的 540 / 720 / 365 根保留，可向左拖动查看。
- 快照 PNG 使用同一默认视图。

### D2-8 视图内过滤（`main.js`，`engine.js`，`primitive.js`）

- 用最后 `visibleBars` 根展示 K 线的最低价和最高价得到 `viewMin` / `viewMax`，`span = viewMax - viewMin`。
- 价值区：`filterValueAreas` 改用 `viewMin` / `viewMax`（原来用全部已加载 K 线）。
- 线（PQ VWAP、nPOC）：价格在 `[viewMin - pad, viewMax + pad]` 内才画，`pad = span × visiblePadPct / 100`。
- 供需区：与 `[viewMin - zPad, viewMax + zPad]` 有交集才画，`zPad = span × zones.viewPadPct / 100`。新增配置 `zones.viewPadPct: 50`。
- 不画的对象仍然出现在表格里，状态追加 `（图外）`。
- `autoscaleInfo` 只包含实际画出的对象。

### D2-9 增量刷新（`data.js`，`main.js`）

- 首次加载和切换币种 / 周期时全量加载，保持现状。
- 之后每 60 秒对每个用到的周期（展示周期、1h、30m、计算周期，去重）各请求一次 `limit=3`、不带 `endTime`，按 `time` 合并进缓存（同 time 替换，新 time 追加），再裁到上限长度。
- 每 30 分钟做一次全量重载，并重新拉取 `profiles-{S}.json`。
- 增量请求失败时保留上次缓存，状态栏显示 `刷新失败，显示 HH:MM 的数据`，**不删除任何已画区域**。
- “Loading x/y” 进度只在全量加载时显示。

### D2-10 CI 与回归（`.github/workflows/pages.yml`，`scripts/d1_smoke.cjs`，`scripts/d1_daily_png.cjs`）

1. `analysis-smoke` 的条件改为 `github.event_name == 'pull_request'`（所有 PR 都跑）。`C4.1 golden-standard archive checks` 同样对所有 PR 运行。
2. `d1_smoke.cjs` 的 mock 行情支持 `1w`（周一锚定）。三个周期 4h / 1h / 1d 都要测，新增断言：
   - 时间轴：`candles.data().length` 等于展示 K 线数；VWAP 每个 time 都属于 K 线 time 集合；默认视图逻辑跨度等于 `visibleBars + rightOffset`，允许 ±2；
   - 视图保持：设置 1h 可视范围 600~700 后调用 `refresh()`，范围偏差 ≤ 1 根；
   - 视图内过滤：`y(viewMin) - y(viewMax) >= 0.6 × 主图 pane 高度`；
   - 增量刷新：一次 `refresh()` 的 fapi 请求数 ≤ 4，每个 `limit <= 3`；
   - 原有的数量上限、价格轴标签误差 ≤ 1px 保留。
3. `d1_daily_png.cjs` 的 manifest 每张图增加字段：`visibleBars`、`logicalSlots`、`calcLastClosedUtc`、`supply`、`demand`、`drawn`、`offView`。出现以下情况时直接失败：
   - `logicalSlots > visibleBars + rightOffset + 2`；
   - `calcLastClosedUtc` 早于 `cutoff - 计算周期 - 1 天`（1D 图的计算周期是 1w，允许落后不足 7 天的当周）。

## 3. 不要改的东西

- `engine.valueArea` 保持单行扩展。PR #9 的探针里，ETH 2025-11 的 30m TPO 70% 就是用它得到 VAL 2707.00（误差 0.04%）。`chart.html` 里的双行版本也不动。
- PQ = 上季 1h anchored VWAP ±1σ；PM = 30m TPO 70%，每行 100 tick；PW = aggTrades 精确成交量分布 70%。
- LWC 5.2.1 仍从 jsDelivr 加载并带 SRI，保留 `attributionLogo`。
- `web/` 下禁止 `Math.min(...)` / `Math.max(...)` 展开写法，用循环。
- 不新增依赖、不引入构建步骤。
