对应他 2026-10-01 BTC 月报第 2 张图的**右下分屏**（BTCUSDT.P，4 小时）。这个分屏只做一件事：看价格相对**滚动 VWAP** 和**往年 VWAP 价值区**的位置。图上有：

- 4 条绿色滚动 VWAP，线的末端写小字 `30D RVWAP`、`60D RVWAP`、`90D RVWAP`、`365D RVWAP`；

- 往年的水平线：`2024 VWAP`（橙色实线，橙色价格框）、`2024 VAH`（白色虚线）、`PY VAL`（白色虚线，PY = 去年）；
- 显示约 4 个月，右侧留白约 18%。他的文字结论“突破 365 天滚动 VWAP 和 2024 VAH 是看涨信号”就来自这张图。

## 2. 实现规格

### D13-1 年度价位预计算（`scripts/d10_build_levels.py`）

- 新增 `kind: "year"`，每天输出**去年**和**前年**两个完整自然年（UTC 1 月 1 日 00:00 到次年 1 月 1 日 00:00）。
- 定义：**4h K 线，hlc3，按成交量加权的锚定 VWAP，σ 用成交量加权的总体标准差；VAH = VWAP + 1σ，VAL = VWAP − 1σ，取年末最后一根 K 线的值**。和季度定义相同，只是周期换成年、K 线换成 4h（他这张图是 4h 图，TradingView 的锚定 VWAP 用图表周期的 K 线计算）。
- 每年输出 3 条：`side` 为 `VWAP`、`VAH`、`VAL`。
- 标签按输出当天的年份生成：去年写 `PY VWAP` / `PY VAH` / `PY VAL`，前年写年份，例如 `2024 VWAP` / `2024 VAH` / `2024 VAL`。缓存按年份存（例如 id `year-2024-vwap`），标签在输出时生成，跨年后自动变成新的 PY 和新的年份。
- 完整性沿用 D11 的 `period_completeness`：`expectedBars = 天数 × 6`（2024 年是 2196），缺口 ≤ 0.5%，最后一根必须在；只缓存 `complete: true` 的结果。
- `definition` 写 `Y / 4h VWAP±1σ (hlc3)`。
- **季度价值模板和综合模板选关键价位时排除 `kind: "year"`**，D12 / D12b 的图不变。

**金标准（写成 `pipeline/tests` 里的联网测试，和现有 D10 金标准测试同样方式）**，BTCUSDT：

| 价位 | 他图上的值 | 允许误差 |
|---|---|---|
| `2024 VWAP` | 64,960.2（橙色价格框，精确值） | ±0.2% |
| `PY VAL`（2025 VAL） | 约 87,280（价格框 87,286.0 / 87,269.5 两个相邻值） | ±0.3% |

如果 4h 结果超出误差，用 1h 再算一次，两组数都写进回复；哪组在误差内就用哪组，并同步改 `definition` 和 DECISIONS。两组都不在误差内时，仍按 4h 实现，DECISIONS 里标“未通过金标准”，回复里给出数值。

### D13-2 滚动 VWAP 和今年 VWAP（前端计算）

在 `web/chart/indicators.js` 新增两个纯函数，并写单元测试：

1. `rollingVwap(bars, windowSec)`：对每根 K 线 i，取开盘时间满足 `t_i − windowSec < t_j ≤ t_i` 的 K 线，`Σ(hlc3 × volume) / Σ volume`。用前缀和实现，3000 根 × 4 个窗口要在 50ms 内。**K 线 i 之前的历史不足一个完整窗口时返回 `null`，图上不画这一段**（不要用不完整窗口凑数）。
2. 今年 VWAP ±1σ：复用 `anchoredVwap`，锚在当年 1 月 1 日 00:00 UTC，用 4h K 线。窗口跨年时，每个自然年各画一段（同 D9 季度灰带的分段做法）。

单元测试至少覆盖：窗口边界（正好 `windowSec` 之前那根被排除）；窗口覆盖全部数据时等于锚定 VWAP；历史不足返回 `null`；中间有缺口时窗口按时间截取（按根数截取会多算缺口之前的 K 线）。

### D13-3 模板“滚动 / 年度 VWAP”

`config/analysis-rules.json` 的 `templates` 新增 `rvwap`，按钮组变成 `季度价值 | 滚动 VWAP | 综合`，URL `tpl=rvwap`。

| 项目 | 规格 |
|---|---|
| 周期 | 只有 `4h` |
| 默认范围 | 最近 120 天（720 根），右侧留白 18%（同 D12） |
| 历史数据 | 需要 365 天 + 120 天 ≈ 2,920 根 4h。模板配置加 `history: {"4h": 3000}`，`data.js` 的 `capFor` 按当前模板取较大值（实时模式分页拉取，Binance 单次上限 1500）；`d1_build_snapshot.py` 的 4h 由 620 根改为 3000 根 |
| 滚动 VWAP | 30D / 60D / 90D / 365D 四条，绿色 `#4caf50` 1.5px；每条线下面先画一条 6px 宽、`rgba(190,196,208,.10)` 的底线（模仿他的图）；线的末端（最后一根 K 线右侧 8px）写 `30D RVWAP` 这类小字，11px 等宽字体，颜色 `#aeb7c8`，左对齐；四个小字之间按现有 `regionLabelLayout` 错开，最小间距 12px |
| 今年 VWAP | 黄色 `#e8d44d` 1.5px；±1σ 两条线 `rgba(190,196,208,.55)` 1px，同样带 6px 底线，**不填充**；黄线末端写 `Y VWAP`，样式同上 |
| 往年水平线 | D13-1 的 6 条候选，只画在价格视图内（含 10% 留白）的；间距规则沿用 D12b（2% 和 18px 取大），离现价近的优先。VWAP 用橙色 `#f5a623` 1.5px 实线、橙色价格框；VAH / VAL 用白色虚线、灰底价格框（同 D12b）；标签写在右端，白色 12px（VWAP 用橙色） |
| 自动缩放 | K 线 + 上面所有线，线的值先限制在 `[视图最低 − 10% 价格范围, 视图最高 + 10% 价格范围]` 内再参与缩放（同季度灰带的做法），远处的线不会把 K 线压扁 |
| 图内信息第 2 行 | `Rolling VWAP (hlc3, 4h)  30D …  60D …  90D …  365D …  ·  Y VWAP …  +1σ …  −1σ …`，十字线移动时显示对应 K 线的值 |
| 关闭 | 季度灰带、季度 / 月份关键价位、PQ 三条线、PM / PW、供需区、nPOC、成交量副图、图例、表格 |
| 保留 | 图内信息第 1 行、水印、价格轴倒计时（D12b） |
