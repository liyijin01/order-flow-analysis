# D11b：在仓库里建立变更记录（docs/）

仓库：https://github.com/liyijin01/order-flow-analysis
基线：main `af1601f`（D11 已合并）
分支：`d11b-docs`
附件：`docs-pack.zip`（我会和本文档一起发给你）

## 0. 执行规则

1. 从最新 main 切分支 `d11b-docs`。
2. 把 `docs-pack.zip` 解压到仓库根目录，得到 `docs/` 目录：`README.md`、`ROADMAP.md`、`CHANGELOG.md`、`DECISIONS.md`、`HANDOFF.md`、`specs/`（17 份历史任务文档）。**文件内容原样提交，不要改写。**
3. 再把本文档原样保存为 `docs/specs/D11b.md`，并在 `docs/CHANGELOG.md` 末尾追加一行：`| D11b | {日期} | {提交} / #{PR} | 建立 docs/：路线图、变更记录、关键决定、交接说明、历史任务文档 | 以后每个 PR 都更新 docs |`。
4. 在仓库根目录 `README.md` 开头加一句：`项目进度、关键决定和历史任务文档见 [docs/](docs/README.md)。`
5. 只有文档改动，不改任何代码。本地跑一遍 `node --test web/tests/*.test.mjs` 和 `python -m unittest discover pipeline/tests -v`，确认没有影响，然后一次性 push，等 CI 跑完。
6. CI 全绿后**直接 squash merge 到 main，不需要等 review**。

## 1. 为什么要做

到目前为止，每一轮“做了什么”在 PR 描述和提交信息里有记录，但下面这些只存在于对话里：任务文档原文、各项定义的验证依据、产品方向的决定、还没做的任务清单。对话一旦达到长度上限，这些就需要重新解释。放进仓库后，任何新对话读 `docs/` 就能接上进度。

## 2. 以后每个 PR 的规则（已写进 `docs/README.md` 和 `docs/HANDOFF.md`）

1. 把本轮任务文档原样保存为 `docs/specs/{编号}.md`；
2. 在 `docs/CHANGELOG.md` 末尾追加一行；
3. 更新 `docs/ROADMAP.md` 的状态；改了定义或规则时同步更新 `docs/DECISIONS.md`。
