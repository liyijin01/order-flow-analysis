## 1. 背景

D12~D17 六张模板都已上线。和他的图对比，问题集中在两张剖面图：

- **价格范围太宽**：周度剖面的价格轴从 45k 到 140k，因为 52 周前的未回补线和所有剖面都参与了缩放，剖面被压得很小。他的月度图只看现价 −16% ~ +25%，周度图只看 −8% ~ +12%。
- **线太多**：周度剖面画了 77 条线，大部分是“被碰过的淡线”（可视范围内每一周的 VAH / VAL / POC 都画到被碰的那一周）。
- **本期已经碰到的线仍显示为未回补**：规则只用已结束的周期判断，这是为了和他一致；但读图时需要知道“这周 / 这个月已经碰过”。

另外 D16 / D17 的对照里有三处和他的图不一致，原因还不清楚，本次先诊断（D18-4）：

1. 2026-08 VAH：我们 81,510，他 77,984（+4.5%）。同一定义下，2025-11 VAH、2026-05 VAH / VAL 都在 ±0.04% 以内。
2. 参考周 Jan W4：选中的周一致，上沿一致（+0.036%），下沿我们 75,500，他约 82,060（−8%）。
3. 两条线他还画着、我们判定为“已被碰到”：2026-01 VAL 87,360（被 9 月最高 87,385.1 碰到，只超出 25 USD）；2026-08-17 那周的 POC 77,305（他的 77,300 黄线还在）。

## 2. 实现规格

### D18-1 剖面模板的价格窗口

- `config/analysis-rules.json`：`mprofile.priceWindowPct: {"below": 18, "above": 25}`，`wprofile.priceWindowPct: {"below": 10, "above": 12}`（大致按他的两张图）。
- 默认视图的价格范围 = `[现价 × (1 − below%), 现价 × (1 + above%)]`；当前周期的剖面必须完整在范围内（超出时把范围扩到它的 high / low）。
- 剖面、未回补线、方框、single print 都**只用这个范围做自动缩放**；范围外的部分照常画，被画布裁掉即可。用户拖动价格轴后按现有逻辑（D3）关闭自动缩放，双击恢复。
- 未回补线、single print 的数量上限（16 / 6）改为只在价格窗口内统计。

### D18-2 被碰过的淡线减量

- 两张剖面图都只画**最近 8 条**被碰过的线（按被碰的时间从新到旧），其余不画。
- 淡线不要价格框、不要文字（现状如此，保持）。
- 配置项：`mprofile.maxTouched: 8`、`wprofile.maxTouched: 8`。

### D18-3 本期已触

- 未回补线（月度、周度剖面）如果**正在形成的周期**的 `[low, high]` 已经包含它，就画成**虚线**，价格框颜色降到 50% 透明度；判定规则不变（它仍算未回补，跨期后才改为已触碰）。
- 图内信息第 2 行把 `naked 7` 改为 `naked 7 (2 this period)` 这种格式。
- `latest.json` 里 `naked` 的每一项加 `touchedThisPeriod: true/false`。

### D18-4 定义诊断（只写进回复和 DECISIONS，除第 3 条外不改定义）

新增 `scripts/d18_diagnostics.py`（联网，从 Binance Vision 取数据，不进 CI），输出三张表：

1. **月度价值区：TPO 和成交量剖面对比**。对 BTCUSDT 2025-11、2026-01、2026-05、2026-08、2026-09 五个月，各算两种 70% 价值区：
   - 现行定义：30m TPO，100 ticks/row；
   - 30m 成交量剖面：每根 30m K 线的成交量平均分到它覆盖的行上，行高同上。

   和他的值逐项比较：2025-11 VAH 102,048；2026-01 VAH 94,304 / VAL 87,424 / POC 89,344；2026-05 VAH 81,200 / VAL 76,376；2026-08 VAH 77,984；2026-09 VAH 83,808 / VAL 74,912 / POC 77,280。每种方法给出逐项误差和平均绝对误差。**本次不改定义**，结论我来判断。
2. **参考周 Jan W4 的下沿**。以下候选值和他的 82,060 比较：该周 full low（75,500）；该周 VAL、POC；按 UTC+8 周界（2026-01-25 16:00 UTC 到 2026-02-01 16:00 UTC）的 low；去掉周日的 low；该周收盘价；前一周（2026-01-19）的 low。列出哪个最接近。
3. **触碰的穿过幅度**。对上面第 3 点的两条线，算出第一个碰到它的已结束周期穿过它的幅度：`min(high − 价位, 价位 − low)`，分别给出 USD 和占价位的百分比。
   - **如果两条都小于 0.1%**：把剖面未回补线的触碰规则改为“穿过至少 0.1% 才算碰到”（`E.profileExtensions` 加一个容差参数，配置 `touchTolerancePct: 0.1`），single print 的回补规则不变；更新单元测试和 DECISIONS。
   - **否则**：不改规则，只记录结果。

### D18-5 数据过期提示

- build job 输出 `analysis/status.json`：`{generatedAt, dataCutoffUtc, levelsGeneratedAt, tpoGeneratedAt, pngCount}`。
- 分析板读取 `analysis/levels/*.json` 和 `analysis/tpo/*.json` 的 `generatedAt`，超过 36 小时就在标题行右侧显示红色小字 `预计算数据已 {N} 小时未更新`；没超过时不显示。快照模式（PNG）不显示。
- 用 smoke 测试覆盖：把 `generatedAt` 改成 40 小时前，提示出现；改回现在，提示消失。

### 测试

- `scripts/d1_smoke.cjs`（`tpl=mprofile` 和 `tpl=wprofile`）：默认价格范围符合 D18-1，当前周期剖面完整可见；淡线 ≤ 8 条；本期已触的线是虚线；其他五个模板的现有断言照常通过。
- 单元测试：价格窗口计算（含当前剖面超出时扩展）；淡线按被碰时间截取 8 条；本期已触判定。
