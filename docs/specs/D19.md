仓库：https://github.com/liyijin01/order-flow-analysis
基线：**D18 合并后的 main**（`7ae3961`，PR #29）
分支：`d19-refactor-templates`
范围：`web/analysis/*`（含新目录 `web/analysis/templates/`）、新目录 `web/shared/`、`web/chart/indicators.js`（只改价值区函数的实现方式）、`analysis.html` / `flow.html` / `chart.html`（只加 `<script>` 引用）、`scripts/`（新脚本和抽出的公共函数）、`.github/workflows/pages.yml`、`web/tests/*`、`pipeline/tests/*`、`docs/`。

**这是纯重构：任何模板的画面、数值、PNG、`latest.json` 都不能变。** 用 D19-1 的安全网证明这一点。

## 0. 执行规则（必须遵守）

1. 从最新 main 切分支，按 D19-1 → D19-3 的顺序做。
2. **你的环境不能本地运行测试，以 CI 为准**：每完成一项就 commit 并 push，等 CI 结果；CI 全绿（含 `model-diff` 为零差异）再做下一项。不再要求“只 push 一次”。
3. 文档：本文档原样保存为 `docs/specs/D19.md`；`docs/CHANGELOG.md` 追加一行（只写 PR 编号）；`docs/ROADMAP.md`：D19 已完成，下一步 D19b（见 §5），之后 D20、D21；`docs/DECISIONS.md` 加一条“重构类 PR 必须 `model-diff` 零差异才能合并”；`docs/HANDOFF.md` 第 4 条和 `docs/README.md` 对应的那句改成：“能本地运行时，push 前先跑单元测试和浏览器回归；不能本地运行时，每完成一项就 push，以 CI 为准”。
4. CI 全绿后**直接 squash merge 到 main，不需要等 review**。merge 后等部署成功，按 §3 自查，按 §4 回复。
5. 对话中途断开时，新对话里说“继续 D19，分支 d19-refactor-templates，看 git log 做到了哪一项”。

## 1. 背景

D12~D18 每一轮都在 `web/analysis/main.js` 里加分支，现在这个文件 72KB，有 16 处 `state.template==='x'` 判断，最长一行 781 个字符；同一个价值区算法在 `engine.js` 和 `indicators.js` 各有一份（Python 里还有一份）。再加 D20 稳定币占比、D21 简报页之前，先把结构理顺。

因为你只能靠 CI 验证，所以**第一步先装一个安全网**：每个 PR 在 CI 里同时跑改动前（base）和改动后（head）的页面，把所有模板算出来的结果逐项比较。重构的每一步都必须零差异。

## 2. 实现规格

### D19-1 安全网：`model-diff`

1. **抽出公共函数**：把 `scripts/d1_smoke.cjs` 里的模拟行情、价位 / TPO / 剖面 fixture 的路由函数（`rows`、`routeMarket`、`routeKeyLevels` 等）原样移到 `scripts/smoke/helpers.cjs`，`d1_smoke.cjs` 改为引用它。行为不变。
2. **新脚本 `scripts/model_snapshot.cjs <页面地址> <输出 json>`**：
   - 用 Playwright 的 `page.clock.setFixedTime('2026-09-27T12:00:00Z')` 固定时间，用上面的模拟行情和 fixture，保证同一份代码跑两次结果完全一样；
   - 跑所有模板、三个币、每个模板允许的周期（季度 1h / 4h、滚动 4h、周度 30m、月线 1M、月度剖面、周度剖面、综合 4h / 1h / 1d，共 30 个组合）；
   - 每个组合输出一份摘要：显示的 K 线数量和首尾时间；`levels`（id、kind、price、from、to、style、color、label、axisLabel、naked、touchedThisPeriod）；`regions`（id、scope / type、bottom、top、from、to）；`curves`（id、点数、首尾两个点）；剖面（start、poc、vah、val、行数）；`infoValues`；信息行两行的文字；可见的价格轴标签 id；默认可视范围；自动缩放的上下限；
   - 另外记录每个组合向 Binance 发出的请求（周期、limit），**D19 只记录不比较**（D19b 会用它证明请求变少了）。
3. **CI job `model-diff`**（`pages.yml`，所有 PR 都跑）：
   - 把 PR 的 base 提交检出到 `_base/`，base 起在 8001 端口、head 起在 8000 端口；
   - 用 **head 里的脚本**分别对两边跑 `model_snapshot.cjs`，逐项比较：数字相对误差 ≤ 1e-9，字符串完全相同；
   - 产物上传两份 JSON 和一份差异报告（`model-diff-report.md`，列出有差异的组合和字段，没有差异就写 `0 differences across 30 cases`）；
   - 分支名以 `d19` 或 `refactor-` 开头时，有差异就失败；其他分支只出报告、不失败（功能类 PR 本来就会改结果）。
4. D19-1 单独一个 commit。它的 CI 结果必须是零差异（这时 base 和 head 的页面代码相同），用来证明安全网本身是稳定的。

### D19-2 把五个新模板拆成独立文件

- 新建 `web/analysis/templates/`，每个模板一个文件：`rvwap.js`、`weekly.js`、`monthly.js`、`mprofile.js`、`wprofile.js`。每个文件注册到 `window.OrderFlowTemplates[id]`，至少包含：
  - `build(ctx)`：现在的 `buildRvwapCurves` / `buildWeeklyVwap` / `buildMonthlyStructure` / `buildMonthlyProfile` / `buildWeeklyProfile`，原样搬过来；
  - `infoLine(ctx, bar, add)`：现在 `updateChartInfo` 里这个模板的分支；
  - `manifestValues(ctx)`：现在写进 `latest.json` 的 `values`。
- `main.js` 里这五个模板的 `state.template==='x'` 分支全部改成查 `OrderFlowTemplates`。`quarter` 和 `combined` 暂时留在 `main.js`（D19b 再拆）。
- `analysis.html` 在 `main.js` 之前按顺序引用这五个文件。
- **新文件按正常格式写**：一行一条语句，单行不超过 160 个字符。搬过来的旧代码顺手重排，逻辑一个字符都不改。
- 每拆一个模板一个 commit，每个 commit 的 `model-diff` 都必须是零差异。
- `profileTemplate()` 这类按模板 id 判断的辅助函数，改成读模板配置里的标志（例如 `hideCandles: true`、`carrier: "1d"`），不要在 `main.js` 里写模板 id。
- 加一个 CI 检查：`main.js` 里 `state.template===` 和 `state.template!==` 合计出现次数 ≤ 4（只允许 `quarter` / `combined` 相关的），超过就失败。

### D19-3 价值区算法合并成一份

- 新建 `web/shared/value-area.js`，注册 `window.OrderFlowValueArea`，包含 `valueArea(rows, binSize, pct)` 和 `tpoProfile(bars, binSize)`。实现以 `engine.js` 现在的版本为准（它和 Python `pipeline/tpo.py` 的一致性已经在 D16 验证过）。
- `engine.js` 和 `indicators.js` 里的同名函数改成调用它，删除重复的实现；`analysis.html`、`flow.html`、`chart.html` 在 `engine.js` / `indicators.js` 之前引用它。
- 单元测试：把现有的 JS / Python 一致性测试扩到所有 fixture（一周 30m fixture 和月线 fixture），JS 和 Python 的 rows、POC、VAH、VAL 完全相同。
- `chart-smoke` job 的分支条件加上 `d19-`，确认实验台 `chart.html` 不受影响。
- `model-diff` 零差异。
