## 2. 目标：一张成品分析图画什么

每个币种、每个周期只出**一张图**，从下到上的图层如下：

| 图层 | 画法 | 数量上限 |
|---|---|---|
| K 线 | 单色：上涨空心、下跌实心 | 显示根数：4h 540 根（90 天）、1h 720 根（30 天）、1D 365 根 |
| **价值区** | 半透明矩形，从该周期结束时刻延伸到最右侧；矩形内右上角写名称 | 3 个：PQ、PM、PW |
| **供应区** | 红色半透明矩形，从形成时刻延伸到最右侧 | 现价上方最近 2 个 |
| **需求区** | 青绿色半透明矩形 | 现价下方最近 2 个 |
| 关键线 | 深绿色 `PQ VWAP` 实线；橙色 `nPOC` 虚线 | nPOC 最多 2 条（离现价最近的） |
| 本季 VWAP | 绿色细线，**不画** ±1σ 填充（避免和区域抢眼） | 1 条 |
| 右侧留白 | `timeScale.rightOffset = 30`，所有矩形和线都延伸进这片留白，文字写在这里 | |

**图外部分，也要出现在导出的 PNG 里：**

- **图例**（图上方）：`■ 价值区` `■ 供应区` `■ 需求区` `━ VWAP` `┅ 未回补 POC`
- **区域表**（图下方）：列为 类型 / 价格区间 / 距现价 % / 状态（未测试、已测试）/ 计算周期 / 数据来源（exact 或 approx）。按价格从高到低排列。
- **信息行**：`{代码} · {周期} · 收 {价格} · 更新于 {JST 时间}`

## 3. 计算规则

所有参数放在新文件 `config/analysis-rules.json` 里，下面写的是默认值。

### 3.1 价值区

| 名称 | 定义 | 数据 | 状态 |
|---|---|---|---|
| **PQ 上季价值区** | 上一季度锚定 VWAP 在季度结束时的 −1σ 到 +1σ；矩形内再画一条深绿色的 `PQ VWAP` 线 | **固定用 1h K 线计算**，和金标准测试一致，与当前显示周期无关 | 已由金标准验证 |
| **PW 上周价值区** | 上一周成交量剖面 70% 价值区（VAL 到 VAH） | `profiles-{SYMBOL}.json` 的 `previous`，这是 aggTrades 精确数据 | exact |
| **PM 上月价值区** | 先按"上月成交量剖面 70% 价值区"计算：有精确阶梯就用精确阶梯，没有就用 1h K 线近似，标 `≈` | 见 3.5，确认参考图的定义后再改 | 待确认 |

**显示规则：**
- 只显示和"可见价格范围上下各扩 10%"有交集的价值区。
- 两个价值区重叠超过较小那个高度的 70% 时，只保留周期更长的那个。

### 3.2 供应区和需求区（底部盘整 + 冲击走势，并用订单流确认）

计算用的周期比显示周期高一级：**1h 图用 4h，4h 图用 1D，1D 图用 1W**。计算需要的 K 线另外加载，至少 400 根，和显示范围无关。

**判定条件（设 ATR 为冲击前一根 K 线的 ATR(14)）：**

1. **冲击**：连续 1 到 3 根 K 线，满足
   - 净涨跌幅 `|最后一根收盘 − 第一根开盘| ≥ 1.5 × ATR`
   - 每根实体都 ≥ 该根振幅的 50%
   - 每根方向都相同
2. **订单流确认**：冲击这几根 K 线的 `Σ(2 × takerBuyBase − volume)` 与冲击方向同号。
3. **底部盘整**：冲击之前**紧挨着**的 1 到 5 根 K 线，每根振幅都 ≤ 1.0 × ATR。从冲击前一根开始往前找，遇到不满足的就停；一根都没有就不成立。
4. **区域范围**：取底部盘整那几根 K 线的最低价到最高价。
   - 向上冲击 → 需求区；靠近现价的一边是上沿，远的一边是下沿。
   - 向下冲击 → 供应区；方向相反。
5. **强度**：净涨跌幅 ÷ ATR，保留 1 位小数，写在标签里。

**状态：**
- 区域形成之后，任何一根 K 线**收盘**突破远端边界 → 失效，删除。
- 价格第一次碰到近端边界 → 标为"已测试"：填充变淡、边框改成虚线。
- 超过 `maxAgeBars`（默认 300 根计算周期 K 线）的区域不显示。

**合并与筛选：**
- 同类型、价格上有重叠的区域合并：取两者范围的并集，强度取较大值，只要有一个未测试，合并后就算未测试。
- 只显示现价上方最近 2 个供应区、下方最近 2 个需求区，而且距现价不超过 20%。

### 3.3 关键线

- **`PQ VWAP`**：上季最终 VWAP，深绿色实线。
- **`nPOC`**：已结束的周、月里还没被回补的 POC。优先用 `profiles-*.json` 的精确周度 POC，没有就用 30m TPO 的 POC。只显示离现价最近的 2 条。

### 3.4 数据加载

- 显示用的 K 线和计算用的 K 线**分开加载**。
- 计算需要的数据：
  - PQ：上季度起点到现在的 1h K 线
  - 供应区 / 需求区：计算周期 K 线 400 根
  - PM / nPOC：上月起点到现在
- 加载时状态栏显示进度，任何一项失败都在区域表里标明"缺失"，不要静默跳过。

### 3.5 确认月度价值区的定义（非阻塞，结果写进 PR）

参考值：ETHUSDT 永续，2025 年 11 月，`PY Nov VAL = 2,705.89`。依次计算下面三种，找出和参考值差距在 0.3% 以内的那一种，把 PM 改成用这个定义：

1. 11 月成交量剖面 70% 价值区的 VAL（Binance Vision 11 月的日度 aggTrades，按阶梯汇总）
2. 11 月 30m TPO 70% 价值区的 VAL
3. 11 月锚定 VWAP −2σ

如果三种都对不上，PM 保持 3.1 的默认定义，并在 PR 里列出三种的计算值。

## 4. 画法规范

- **颜色：**
  - 供应区：填充 `rgba(239,83,80,.20)`，边框 `#ef5350`
  - 需求区：填充 `rgba(38,166,154,.20)`，边框 `#26a69a`
  - 已测试的区域：填充透明度降到 `.08`，边框改为虚线
  - PQ：`rgba(96,165,250,.10)`，边框 `rgba(96,165,250,.6)`
  - PM：`rgba(251,191,36,.10)`，边框 `rgba(251,191,36,.6)`
  - PW：`rgba(167,139,250,.12)`，边框 `rgba(167,139,250,.7)`
  - VWAP：`#5cb85c`，PQ VWAP：`#2e7d32`，nPOC：`#ff9800`
- **区域文字**：12px、字重 600、颜色和边框相同，写在矩形内的右上角。格式例子：`供应区 · 4h · 2.1ATR`、`需求区·已测试 · 1D · 1.7ATR`、`上季价值区 PQ`。矩形高度不够 16px 时，文字放在矩形上沿的外侧。
- **价格轴标签：**
  - 每个区域只标靠近现价的那条边；价值区标 VAH 和 VAL。
  - **价格轴标签永远显示在真实价格的位置，绝不挪动。** 两个标签间距小于 14px 时，隐藏优先级低的那个（它仍然会出现在区域表里）。优先级：供应区 / 需求区 > 价值区 > 关键线。
- **文字防重叠：**
  - 每一帧在 `draw()` 里用当前价格轴实时计算坐标，**不要把像素坐标缓存到 item 上**，这是问题 4 的根源。
  - 文字最多偏离自己的目标 24px，放不下就隐藏。
- **成交量副图**：使用 volume 格式（K / M），不套用价格格式。

## 7. 参考实现（供应区 / 需求区）

下面这段就是生成 `target-analysis-eth-1h.png` 时用的逻辑，改成了循环写法，因为 CI 禁止 `Math.min(...arr)` 这种展开写法：

```js
function atr14(bars){const out=[];let a=0;for(let i=0;i<bars.length;i++){const b=bars[i],pc=i?bars[i-1].close:b.open;const tr=Math.max(b.high-b.low,Math.abs(b.high-pc),Math.abs(b.low-pc));a=i<14?(a*i+tr)/(i+1):(a*13+tr)/14;out.push(a);}return out;}
function detectZones(bars,cfg){ // bars: 计算周期 K 线，需要 open/high/low/close/volume/takerBuyBase/time
  const atr=atr14(bars),zones=[];
  for(let i=20;i<bars.length-1;i++){
    for(let n=1;n<=cfg.impulseMaxBars;n++){
      if(i+n>bars.length)break;
      const first=bars[i],lastB=bars[i+n-1],move=lastB.close-first.open,A=atr[i-1];
      if(Math.abs(move)<cfg.impulseMinMoveAtr*A)continue;
      let ok=true,delta=0;
      for(let k=i;k<i+n;k++){const b=bars[k],body=Math.abs(b.close-b.open),range=b.high-b.low;
        if(body<cfg.impulseMinBodyPct*range||Math.sign(b.close-b.open)!==Math.sign(move)){ok=false;break;}
        delta+=2*b.takerBuyBase-b.volume;}
      if(!ok||(cfg.requireDeltaAlign&&Math.sign(delta)!==Math.sign(move)))continue;
      let lo=Infinity,hi=-Infinity,count=0,start=null;
      for(let j=i-1;j>=Math.max(0,i-cfg.baseMaxBars);j--){const b=bars[j];if(b.high-b.low>cfg.baseMaxRangeAtr*A)break;
        if(b.low<lo)lo=b.low;if(b.high>hi)hi=b.high;count++;start=b.time;}
      if(!count)continue;
      zones.push({type:move>0?'demand':'supply',from:start,created:lastB.time,top:hi,bottom:lo,strength:Math.abs(move)/A});
      break;
    }
  }
  for(const z of zones){z.tested=false;z.valid=true;
    for(const b of bars){if(b.time<=z.created)continue;
      if(z.type==='demand'){if(b.close<z.bottom){z.valid=false;break;}if(b.low<=z.top)z.tested=true;}
      else{if(b.close>z.top){z.valid=false;break;}if(b.high>=z.bottom)z.tested=true;}}}
  return zones.filter(z=>z.valid);
}
```

默认参数：`impulseMaxBars 3, impulseMinMoveAtr 1.5, impulseMinBodyPct 0.5, requireDeltaAlign true, baseMaxBars 5, baseMaxRangeAtr 1.0, maxAgeBars 300, perSide 2, maxDistancePct 20`。

## 8. 测试（CI 必须通过）

1. **区域识别**：用构造的 K 线测试
   - "盘整 + 向上冲击"识别为需求区，"盘整 + 向下冲击"识别为供应区
   - delta 方向相反时不成立
   - 收盘突破远端边界后失效
   - 碰到近端边界后标为已测试
   - 重叠区域能正确合并
2. **数量上限**：每侧最多 2 个区域，价值区最多 3 个，nPOC 最多 2 条。
3. **价格轴标签位置**：缩放价格轴、平移、刷新数据之后，所有价格轴标签的 y 坐标和 `priceToCoordinate(价格)` 的差距都 ≤ 1px。
4. **数据独立**：1h 图也必须能显示 PQ 价值区。
5. **每日 PNG**：生成 9 张 PNG，每张大于 50KB；`latest.json` 的字段齐全。
6. **原有测试**：C4.1 的金标准测试和其他测试继续通过。
