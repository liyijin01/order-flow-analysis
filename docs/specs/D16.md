## 1. 背景

对应他 2026-10-01 BTC 月报的**第 3 张图**（`BTCUSDT, M30`，模板名 `KBeast.ETH Monthly`）。这张图**没有 K 线**，只有：

- 每个月一个横向剖面，从当月 1 日开始向右长；价值区内的行是青色，价值区外是灰色；
- 已结束月份的 VAH / VAL（青色线）和 POC（黄色线）向右延伸；**被后面已结束的月份碰到就停在那个月**，没碰到就一直画到右边缘，价格轴上有青色 / 黄色价格框；
- 当前月份（10 月）的剖面正在形成，它的 POC 也有一条黄线；
- 一个白色方框：**去年 11 月的价值区**（上沿 102,048，下沿约 81,200），从 11 月一直画到右边缘。他的文字：“价格在去年 11 月的价值区里，这个价值区的 VAL 和 5 月 VAH 重合”；
- 他手写了 `May VAH`、`Aug VAH`、`May VAL` 三条线的文字（这三条已被碰过，是他手动挑的，本次不自动画）；
- 右边留白很宽（约 40%）。

我按他图上价格轴的数字核对过“被后面已结束的月份碰到就停”这条规则：在他图的可见价格范围内（约 71k~105k），一直延伸到右边缘、没写文字的青线和黄线正好是 2025-11 VAH、2026-01 VAH / VAL / POC、2026-09 VAH / VAL / POC，都没被后面已结束的月份碰到（2026-09 后面还没有已结束的月份，10 月碰到的不算）。可见范围以下（例如 8 月 VAL）可能还有没被碰到的线，我们的图价格范围更大，会画出来，这是预期的。

**剖面定义沿用 DECISIONS 里已验证的 PM 定义：30m TPO，70% 价值区，100 ticks/row，单行扩展**（`pipeline/tpo.py` 和 `E.tpoProfile`）。D10 已经按这个定义算出 BTC 2025-11 VAH = 102,030，对他图上的 102,048 误差 0.018%。

## 2. 实现规格

### D16-1 TPO 剖面预计算（`scripts/d16_build_tpo.py`）

- 每天输出 `analysis/tpo/{SYMBOL}.json`，`monthly` 数组包含**最近 12 个已结束的月份**，每个月：`start`、`end`、`complete`、`bars`、`expectedBars`、`rowSize`、`poc`、`vah`、`val`、`high`、`low`、`rows`（`[[行下沿价格, TPO 数], …]`，定义精度，100 ticks/row）。
- 计算复用 `pipeline/tpo.py` 和 D10 的 `monthly_tpo_levels` 逻辑（改成同时返回 rows、poc、high、low），不要另写一套。
- 完整性沿用 D11 的 `period_completeness`；只缓存 `complete: true` 的月份，缓存放 data 分支 `tpo/monthly/{SYMBOL}-{YYYY-MM}.json`，以后每天只算新结束的月份。
- `pages.yml`：data job 构建并持久化 `tpo/`（和 `levels/` 一样），build job 把 `_generated/analysis/tpo/*.json` 拷到 `_site/analysis/tpo/`。
- 页面在实时和快照模式都读这个文件（同 levels 的加载方式，带 `generatedAt` 缓存参数）。**当前月份**的剖面在前端用 30m K 线和 `E.tpoProfile` 现算。
- 加一个一致性测试：同一段 30m 数据（用一周的固定数据即可），Python 和 `E.tpoProfile` 算出的 rows、POC、VAH、VAL 完全相同。

### D16-2 通用剖面图层（D17 会复用）

在 primitive 里加一个通用的剖面图层，输入 `profiles: [{start, end, rows, rowSize, vah, val, poc, colors, forming}]`：

- 每个剖面从 `start` 的 x 开始向右画横条，最长那一行占这个周期像素宽度的 85%；
- **显示行**：把定义行按像素合并（每个显示行至少 2px 高，计数相加），缩放后重新合并；显示行的中点在 `[val, vah]` 内用价值区颜色，否则用灰色；POC 所在的显示行用黄色；
- 颜色由调用方传入（月度：价值区 `rgba(64,160,190,.85)`，区外 `rgba(150,150,150,.6)`，POC `#ffeb3b`）。

### D16-3 模板“月度剖面”

`templates` 新增 `mprofile`，按钮组加 `月度剖面`（放在 `月线结构` 后面），URL `tpl=mprofile`。

| 项目 | 规格 |
|---|---|
| 时间轴 | 用 1d K 线做时间轴载体，**K 线不显示**（颜色全透明）；保留最新价的虚线和价格框。周期按钮只显示一个 `M30`（表示剖面用 30m TPO） |
| 水印 | `BTCUSDT.P, M30 Monthly` |
| 默认范围 | 最近 12 个月（11 个已结束 + 当前月），右侧留白 30% |
| 剖面 | D16-2 图层，每月一个；当前月标 `forming`，同样画 |
| 未回补线 | 已结束月份的 VAH、VAL（青色 `#40a0be` 1px）和 POC（黄色 `#e6d600` 1px），从该月 `start` 向右。**只用后面已结束月份的 `[low, high]` 判断是否被碰到**（正在形成的月份不算）。被碰到：线停在第一个碰到它的月份的 `start`，透明度 0.45，没有价格框和文字。没被碰到：画到右边缘，有价格框（青底 / 黄底，深色字），右端写 `Jan VAH`、`Sep POC` 这种 11px 小字（同色，按 `regionLabelLayout` 错开） |
| 当前月 POC | 黄色虚线画到右边缘，右端写 `Oct POC`，有价格框 |
| 价值区方框 | 窗口里已结束的月份中，**价值区包含现价、离现在最近**的那个月：白色 1px 边框、`rgba(255,255,255,.03)` 填充，从该月 `start` 画到右边缘；框内右上角写 `PY Nov VA`（去年的月份加 `PY`，今年的写 `Sep VA`）。没有符合的月份就不画 |
| 自动缩放 | 剖面（各月 high / low）+ 未回补线 + 方框，线的值先限制在视图 ±10% 价格范围内（同 D13） |
| 图内信息第 2 行 | `Monthly TPO (30m, 70%)  Oct POC …  VAH …  VAL …  ·  Box PY Nov VA … / …  ·  naked 7`（最后一个数是未回补线条数） |
| 关闭 | 其他所有图层、成交量副图、图例、表格、收盘倒计时 |
