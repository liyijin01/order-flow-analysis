## 2. 修复规格

### D11-1 只缓存数据完整的周期（`scripts/d10_build_levels.py`）

- 计算一个周期前先检查数据完整性：
  - 1h：K 线根数 = 周期小时数，且最后一根的开盘时间 = 周期结束 − 1h；
  - 30m：同理按 30 分钟算。
  - Binance 历史上偶尔有整点缺失。允许缺口不超过 0.5%，但最后一根必须存在。
- 不完整：本次跳过这个周期，打印 `::warning::`，**不写入缓存**，第二天再算。页面上这个周期暂时不出现。
- 完整：照常计算，缓存记录增加 `bars`、`expectedBars`、`complete: true`。
- 读取缓存时，没有 `complete: true` 的记录一律视为无效、重新计算。这样现有缓存（包括少算了一天的 Q3）会在下一次运行时自动重算一遍，不需要手动改 data 分支。
- Python 测试：模拟最后一天缺失时不写缓存；模拟中间缺 1 根时照常计算；旧格式缓存会被重算。

### D11-2 只画图上已经结束的周期（`web/analysis/main.js`）

- 只使用 `periodEnd ≤ 图上最后一根已收盘 K 线的收盘时间` 的价位。快照模式用 `cutoffUtc`，实时模式用当前时间。
- 测试：用截止 9/29 的快照加上含 Q3 的价位文件，图上和表格里都不出现 Q3。

### D11-3 选线规则贴近他的图（`web/analysis/engine.js`，`config/analysis-rules.json`）

- 新增配置：`keyLevels.maxCount: 6`（已有）、`keyLevels.maxMonthly: 2`、`keyLevels.minGapPct: 2`。
- 选线顺序：
  1. 候选限定为视图价格范围 ± `visiblePadPct` 内、排除上一季度（与 D10 相同）。
  2. 先选季度类（今年季度和 PY 季度），按离现价由近到远；
  3. 再选去年月份类，最多 `maxMonthly` 条；
  4. 任意两条已选的线，价格差至少为视图价格跨度的 `minGapPct`%。太近的跳过，不影响继续往下选。PQ 矩形的上下沿也按已选的线参与这个间距判断。
  5. 总数不超过 `maxCount`。
- 合并规则（相差 < 1 tick 合并为一个标签）保持不变，合并发生在选线之前。
- 单测：给定 12 个季度候选和 24 个月份候选，选出的月份线 ≤ 2；任意两条间距 ≥ minGapPct；季度候选足够时优先选季度。

### D11-4 表格只列图上画出的价位（`web/analysis/main.js`，`web/analysis/export.js`）

- 表格里的关键价位只列出**图上实际画出**的那几条；其余合并成一行：`关键价位 · 另有 N 条不在当前视图`。
- 其他行（价值区、供需区、nPOC、PQ VWAP）保持现状。
- PNG 导出用同一份表格数据。
- 每日 PNG 的高度回到 D9 的水平：`d1_daily_png.cjs` 断言每张 PNG 的高度 ≤ 1,300px。
