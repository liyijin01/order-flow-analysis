## 1. 背景

对应他 2026-10-01 BTC 月报的**第 4 张图**（`BTCUSDT, M30`，模板名 `KBEAST.ETH Weekly`）。和第 3 张图一样**没有 K 线**，只有每周一个剖面：

- 价值区内的行是橙色，区外是灰色，POC 那一行黄色；
- 未回补的周 POC（黄色线）和周 VAH / VAL（橙色线）向右延伸，价格轴上有黄色 / 橙色价格框；
- 一个灰色方框加两条青色边线（82,060 ~ 90,560），他的文字：“周线守在 1 月第 4 周的区间之上，那里还有一个未回补的 nPOC”；
- 他文字里还提到“9 月的 single print 没有回补”。他第 3 张图里成对出现的橄榄色线（例如 86,016 / 85,664、82,528 / 82,336、80,032 / 79,296）很可能就是 single print 的上下沿；
- 还有一个他手工合并的 `4 WEEKS` 复合剖面，本次不做。

## 2. 实现规格

### D17-1 周度剖面数据

- `scripts/d16_build_tpo.py` 的输出加 `weekly` 数组：**最近 52 个已结束的周**的摘要（`start`、`end`、`complete`、`poc`、`vah`、`val`、`high`、`low`），其中最近 26 周再带 `rows`。
- 周：周一 00:00 UTC 到下周一 00:00 UTC（同 D14）。定义和月度相同：**30m TPO，70%，100 ticks/row，单行扩展**。注意这和综合模板 PW 的逐笔成交量剖面定义不同，DECISIONS 里写清楚。
- 完整性和缓存同 D16：只缓存 `complete: true` 的周，缓存放 data 分支 `tpo/weekly/{SYMBOL}-{YYYY-MM-DD}.json`（周一日期）。
- 当前周的剖面在前端用 30m 现算（D14 的 30m 历史已经够）。

### D17-2 模板“周度剖面”

`templates` 新增 `wprofile`，按钮组加 `周度剖面`（放在 `月度剖面` 后面），URL `tpl=wprofile`。大部分沿用 D16：

| 项目 | 规格 |
|---|---|
| 时间轴 | 同 D16：1d K 线做载体、不显示；周期按钮只显示 `M30`；水印 `BTCUSDT.P, M30 Weekly` |
| 默认范围 | 最近 26 周（25 个已结束 + 当前周），右侧留白 30% |
| 剖面 | D16 的通用剖面图层，每周一个；颜色：价值区 `rgba(255,152,0,.9)`，区外 `rgba(150,150,150,.6)`，POC 行 `#ffeb3b` |
| 未回补线 | 规则同 D16（只用后面**已结束的周**判断是否被碰到；被碰到就停在那一周、变淡、无价格框）。POC 黄色 `#e6d600`，VAH / VAL 橙色 `#ff9800`，都是 1px。没被碰到的线**最多画 16 条**，离现价近的优先，POC 优先于 VAH / VAL。**不写右端文字**（同他的图），只有价格框 |
| 当前周 POC | 黄色虚线画到右边缘，有价格框 |
| 参考周方框 | 见 D17-3 |
| single print | 见 D17-4 |
| 图内信息第 2 行 | `Weekly TPO (30m, 70%)  POC …  VAH …  VAL …  ·  Ref Jan W4 … / …  ·  nPOC 5  ·  SP 3` |
| 关闭 | 其他所有图层、成交量副图、图例、表格、收盘倒计时 |

### D17-3 参考周方框（近似算法）

- **自动选择**：在“52 周前到 5 周前”的已结束周里（不含最近 4 周），找区间 `[low, high]` 包含现价的周，取振幅 `(high − low) / low` 最大的那一周。没有就不画。
- **手动指定**：`config/analysis-rules.json` 加 `wprofile.referenceWeek: {"BTCUSDT": null, "ETHUSDT": null, "SOLUSDT": null}`，填周一日期（例如 `"2026-01-26"`）时用指定的周，`null` 时自动选择。
- 画法：从那一周的 `start` 画到右边缘（周在窗口左边之外时从左边缘开始），填充 `rgba(190,196,208,.08)`，上下沿青色 `#40a0be` 1px 线加青色价格框；框内左上角写 `Jan W4 range`（月份英文缩写 + 当月第几个周一 + `range`，白色 11px）。

### D17-4 single print（月度剖面和周度剖面都加）

- **定义**：一个已结束周期的定义行里，TPO 数等于 1 的连续行；**不含剖面最上和最下两端的单印尾巴**（直接复用 `indicators.js` 的 `singlePrintRanges`，它已经跳过两端）；高度至少 `max(3 行, 现价的 0.15%)`。
- 预计算：`d16_build_tpo.py` 给每个已结束的月和周输出 `singlePrints: [[bottom, top], …]`（周期数据不变，所以可以缓存）。
- **回补**：和 D15 imbalance 同样处理，只用后面**已结束周期**的 `[low, high]`：被碰到的部分去掉，剩下没碰到的部分；全部被碰到就不画。
- 画法：从那个周期的 `start` 画到右边缘，上下沿橄榄色 `#a8a23a` 1px 线、填充 `rgba(168,162,58,.10)`，上下沿都有橄榄色价格框；每个模板最多画 6 段，离现价近的优先。
- 月度剖面模板（D16）的信息第 2 行末尾加 `·  SP n`。
