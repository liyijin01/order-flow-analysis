## 2. 数据探针（P0，先做）

脚本 `scripts/d6_probe.py`，用一次性 workflow 在 PR 分支上运行，产物上传 artifact。merge 前删除该 workflow（沿用 D4 删除 d1-monthly-probe 的做法）。

### 2.1 bookDepth

下载 `data.binance.vision/data/futures/um/daily/bookDepth/{BTCUSDT,ETHUSDT,SOLUSDT}/` 最近 3 个完整 UTC 日的 zip 与 `.CHECKSUM`，逐项报告：

- 是否有表头，列名与顺序
- timestamp 的格式与单位（字符串 / ms / µs），按数值量级判定
- 实际快照间隔的分布（min / p50 / p95 / max），不要假设固定 30s
- percentage 档位全集，特别确认是否存在 ±2.5
- 负档位对应 bid 还是 ask：用 notional / depth 反推均价，和同时刻 1m K 线收盘价核对
- depth 与 notional 是否为“从中间价到该档”的累计值（检查随档位单调不减）
- 该数据集最早可用日期

该数据集没有正式文档，历史上有 notional/depth 与同期价格不一致的时段，必须按“不可信输入”处理，校验失败即剔除。

### 2.2 klines

- 确认 quote volume（index 7）与 taker buy quote volume（index 10）

## 4. 模块 A：锚定 VWAP 带（P0）

### 4.1 计算

- 计算序列：USD-M 永续 15m K 线
- 价格与权重：沿用现有 anchored VWAP 函数的定义（典型价与成交量权重以现有代码为准）；如果现有定义与 hlc3 × volume 不同，保持现有并在 PR 注明
- σ：沿用现有 ±1σ 的定义（成交量加权标准差），逐 bar 更新，画成曲线带
- 30m 显示时仍用 15m 计算，再对齐到 30m 显示 bar 的时间戳；对齐方法沿用 D2-1，不允许产生额外逻辑时间槽

### 4.2 显示

- VWAP 实线；±1σ 之间半透明填充；±2σ 细线
- 倍数写进 config：`bands: [1, 2]`，填充只作用于第一个倍数

### 4.3 锚点规则（确定性）

锚点模式：`swing`（默认）、`week`、`quarter`、`manual`。页面下拉切换；PNG 一律用 `swing`。

1. `swing`：在截至最后一根已收盘 15m bar 的回看窗口 L 内（默认 14 个 UTC 日，config），找最高 high 与最低 low，锚点取两者中较早出现的那根 bar 的开盘时间，即主导波段的起点。并列时取最早。未收盘的 live bar 不参与锚点选择。
2. `week`：本周一 00:00 UTC。
3. `quarter`：本季度起点，直接复用 analysis board 的本季度 1h VWAP 序列并对齐，标签注明 `1h calc`。
4. `manual`：URL 参数 `?avwapAnchor=2026-09-21T00:00Z`，必须对齐到 15m bar 开盘时间，否则报错。

锚点必须落在已加载的计算数据内；数据不够就向前分页加载；加载失败显示错误，禁止静默截断锚点。锚点处画竖线并标 `AVWAP anchor`。

## 5. 模块 B：现货与合约 CVD 分开（P0）

- 数据：Binance K 线自带主动买入量。永续 `/fapi/v1/klines`，现货 `/api/v3/klines`，同一 symbol；增量刷新沿用 D2-9 的 `limit=3` 策略，两个市场各一次
- 单位统一为 USDT 名义额，方便两条线横向对比：
  - `delta = 2 × takerBuyQuote - quoteVolume`（index 10 与 index 7）
- CVD 从已加载显示窗口的第一根 bar 开始累计，起点为 0；pane 标签写明起点时间；切换币种、周期、重置视图时重算
- 缺 bar：该处断线，禁止补 0，禁止插值
- spot 与 perp 的 bar 必须对齐到同一组 display timestamps；某一边缺失时只有那一边断线
- 未收盘 bar：显示，但末段用淡色区分；snapshot 只用已收盘 bar
- 数值格式：带正负号的 K / M / B
- 不做跨交易所聚合，标签写 `Binance Perp` / `Binance Spot`

## 6. 模块 C：订单簿分档深度（P0）

### 6.1 数据源

- `data.binance.vision` USD-M 每日 bookDepth。Binance 没有现货 bookDepth 归档，标签写明 `Binance USD-M book`
- 浏览器不直接访问 data.binance.vision。由 Actions 构建静态 JSON：`flow/data/depth-{SYMBOL}.json`，覆盖最近 21 个完整 UTC 日
- 每日处理结果持久化到 data 分支：`depth/{SYMBOL}/{YYYY-MM-DD}.json.gz`，处理完删除原始 zip（沿用 ladders 模式）；校验 `.CHECKSUM`，失败重下一次，仍失败记为缺失日，不插值

### 6.2 分档

- config：`depthBuckets`，默认 `[[0,1],[1,2.5],[2.5,5]]`
- 每个边界必须属于 §2.1 探针得到的档位集合。若 2.5 不存在，默认改为 `[[0,1],[1,2],[2,5]]`，pane 标签与 PR 都写明“数据源无 2.5% 档，改用 1-2% / 2-5%”
- 严禁插值，严禁用相邻档估算不存在的边界
- pane 标签一律从实际使用的边界生成，不写死文字

### 6.3 计算

- 区间 (a, b] 的 bid 名义额 = `cum_bid(b) - cum_bid(a)`；a = 0 时为 `cum_bid(b)`；ask 同理
- `delta = bid - ask`，正值绿色，负值红色
- 采样：每根显示 bar 取“bar 收盘时刻及之前最后一个快照”（as-of join），最大容忍 1 个 bar 长度；没有则该 bar 为空

### 6.4 校验与剔除

逐快照检查，失败即剔除，剔除数写进 manifest：

- 档位缺失或重复
- 同一时间戳重复、时间倒序
- 负值、非有限值
- 累计值随档位不单调
- 由 notional / depth 反推的均价偏离同时刻 1m 收盘价超过“该档宽度 + 0.5%”（阈值放 config）

### 6.5 实时性

- bookDepth 只有到上一个完整 UTC 日的归档。深度 pane 在截止处画竖线，标签写 `depth archive through YYYY-MM-DD 23:59 UTC`
- 截止之后留空，禁止用 REST depth 或其它来源拼接，禁止外推
