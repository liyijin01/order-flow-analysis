## 2. 修复规格

### D4-1 加载调度：同一时间只允许一个加载（`web/analysis/main.js`）

- 新增 `state.inFlight`，保存当前加载的 Promise 或 null。
- **定时器触发的刷新**：`state.inFlight` 不为空，或 `document.hidden === true` 时直接跳过，不递增 `loadToken`。
- **用户操作**（切换币种 / 周期）：照常递增 `loadToken` 并发起新加载。D3 的“重置视图”不触发加载，不受影响。前一个加载用 `AbortController` 取消：`fetchHistory` / `fetchLatest` / `fetchProfile` 都接收 `signal`，被取消的请求不计入 `errors`。
- 页面从后台切回前台（`visibilitychange`）时，如果距上次成功刷新超过 `refreshSeconds`，立即刷新一次。
- 切换币种 / 周期时，立刻更新按钮的 active 状态和标题（显示“加载中”），不要等数据回来。

### D4-2 失败周期自动补全（`web/analysis/data.js`，`web/analysis/main.js`）

- `refreshLiveBundle` 对每个需要的周期先检查：`bundle.errors[interval]` 存在，或者 `series[interval]` 的长度小于 `capFor(interval, timeframe)` 的 50%。满足任一条件时，这个周期改为 `fetchHistory(symbol, interval, capFor(...))` 全量拉取；成功后删除 `errors[interval]`。其他周期照旧只拉 `limit=3`。
- `bundle.profile` 为空（`errors.profile` 存在）时，每次刷新都重新 `fetchProfile`，成功后删除 `errors.profile`。同源小文件，开销可以忽略。
- 全量补拉同样受 D4-1 的单加载规则约束。

### D4-3 默认视窗按宽度自适应（`web/analysis/main.js`，`config/analysis-rules.json`）

- 新增配置 `display.minBarSpacingPx: 5`。
- 默认视窗计算（D3 的“重置视图”也用它）：
  - `ratio = display.rightOffset / visibleBars[tf]`（桌面现状：4h 与 1D 为 30/180，1h 为 30/240）
  - `fit = floor(paneWidth / (minBarSpacingPx × (1 + ratio)))`，`paneWidth = chart.timeScale().width()`
  - `visible = max(30, min(visibleBars[tf], fit))`
  - `rightOffsetBars = max(3, round(visible × ratio))`
  - `setVisibleLogicalRange({from: n - visible, to: n - 1 + rightOffsetBars})`，同时 `timeScale().applyOptions({rightOffset: rightOffsetBars})`
- D2-8 的视图内过滤（`viewMin` / `viewMax`）改用同一个 `visible`，保证“图外”的判断和实际画面一致。
- 窗口尺寸变化（手机横竖屏切换）时：如果当前视图仍是上一次设置的默认视图（逻辑范围差 ≤ 0.5 根），按新宽度重新套用默认视窗；用户手动调过的视图不动。
- 快照 PNG 是 1600px 宽，计算结果仍然是 180 / 240，输出不变。

### D4-4 时间显示（`web/analysis/main.js`）

- 实时模式标题行：`… · 收 {价格} · 最后刷新 {HH:MM:SS} JST`，时间取最近一次成功刷新（全量或增量）的本地时间。刷新失败时沿用 D2 的状态栏提示。
- 快照模式标题行：`… · 收 {价格} · 数据截至 {cutoffUtc 换算成 JST，YYYY/MM/DD HH:MM}`。
- PNG 导出标题沿用这一行，不需要单独改。

### D4-5 CI 维护（`.github/workflows/pages.yml` 等）

- 所有 job 的 `runs-on` 固定为 `ubuntu-24.04`，避免 10 月 19 日镜像迁移带来的意外变化。
- 把用到的官方 action（checkout、setup-node、setup-python、upload-artifact、download-artifact、configure-pages、upload-pages-artifact、deploy-pages）升级到已经原生支持 Node 24 的最新大版本。版本号以各 action 仓库的 release notes 为准；升级后 Actions 页面不能再出现 Node.js 20 的弃用警告。如果某个 action 还没有 Node 24 版本，保持原版本，并在回复里说明。
- 删除 `.github/workflows/d1-monthly-probe.yml`。`scripts/d1_monthly_probe.py` 保留，用于以后复现探针结果。

## 3. 回归测试（`scripts/d1_smoke.cjs`，CI 的 analysis-smoke）

1. **慢网络切换**：用 `page.route` 把 `config/analysis-rules.json` 的 `refreshSeconds` 改成 3，并让每个 fapi 请求延迟 1.2 秒。加载完成后点 ETH：20 秒内显示 ETH；ETH 1h 的 `limit=1500` 请求恰好 3 个。
2. **后台不刷新**：`document.hidden` 为 true 期间（可以用 `Object.defineProperty` 模拟并派发 `visibilitychange`），5 个刷新周期内 fapi 请求数为 0；切回前台后 2 秒内至少刷新一次。
3. **失败补全**：让 30m 的第一次请求返回 500。加载后 PM 缺失；调用一次 `__analysisDebug.refresh()` 后，PM 价值区出现，`state.bundle.errors['30m']` 不存在，`series['30m'].length >= 3000`，状态栏不再显示“缺失”。对 `profiles-*.json` 首次返回 404 做同样的测试，一次刷新后 PW 恢复为 exact。
4. **手机视窗**：视口 390×844、`deviceScaleFactor 3`、`isMobile`。ETH 4h 的 `timeScale().options().barSpacing >= 5`；`document.documentElement.scrollWidth === clientWidth`（没有横向滚动）；`model.visibleBars` 等于第 2 节算出的 `visible`。
5. **时间显示**：实时模式标题行包含“最后刷新”，时间与当前时间相差不超过 70 秒；快照模式包含“数据截至”。
6. D2、D3 已有的断言全部保留。
