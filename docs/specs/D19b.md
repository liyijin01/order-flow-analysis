# D19b：重构第二步（季度 / 综合拆分、按需拉数据、smoke 拆分），画面和数值不变

仓库：https://github.com/liyijin01/order-flow-analysis
基线：**D19 合并后的 main**（`1dcc5ad`，PR #30）
分支：`d19b-refactor-data`（以 `d19` 开头，`model-diff` 严格模式）
范围：`web/analysis/*`（含 `templates/`，新目录 `layers/`）、`web/analysis/data.js`、`config/analysis-rules.json`、`analysis.html`（只加 `<script>` 引用）、`scripts/model_snapshot.cjs`、`scripts/model_diff.cjs`、`scripts/smoke/*`、`scripts/d1_smoke.cjs`、`scripts/d1_daily_png.cjs`、`.github/workflows/pages.yml`、`web/tests/*`、`docs/`。`flow.html`、`chart.html` 不动。

**仍然是纯重构**：模板的画面、数值、PNG、`latest.json` 都不能变。唯一允许变的是向 Binance 发出的请求（要变少）。

1. 从最新 main 切分支，按 D19b-1 → D19b-4 的顺序做。
2. 以 CI 为准：每完成一项就 commit 并 push，CI 全绿（含 `model-diff` 零差异）再做下一项。能本地运行时，push 前先跑单元测试和浏览器回归。
3. 文档：本文档原样保存为 `docs/specs/D19b.md`；`docs/CHANGELOG.md` 追加一行（只写 PR 编号）；`docs/ROADMAP.md`：D19b 已完成，下一步 D20（稳定币占比），之后 D21；`docs/DECISIONS.md` 加一条“新模板和新图层必须声明自己需要的数据；`main.js` 里不写任何模板 id”。
4. CI 全绿后**直接 squash merge 到 main，不需要等 review**。merge 后等部署成功，按 §3 自查，按 §4 回复。
5. 对话中途断开时，新对话里说“继续 D19b，分支 d19b-refactor-data，看 git log 做到了哪一项”。

## 1. 背景

D19 的安全网工作正常：我在本地用同样的脚本跑了 D18 和 D19 两个版本，结果是 `0 differences across 30 cases`。五个新模板已经拆出去，`main.js` 从 72KB 降到 55KB。

还剩三件事：

1. **季度和综合两个模板**的逻辑（PQ / PM / PW 价值区、供需区、nPOC、季度灰带、关键价位）还在 `main.js`，而且**所有模板都会算一遍**，用不到也算。
2. **数据请求浪费**：按 D19 的请求记录，一次打开页面，季度 1h 要发 8 次请求，滚动 VWAP 10 次，月度 / 周度剖面各 9 次。真正需要的大约是 4、2、2、2 次。原因是不管什么模板，都会拉 1h 5000 根和 30m 3500 根。
3. `scripts/d1_smoke.cjs` 还是一个大文件，出错时很难定位到具体模板。

这次的改动比 D19 深（要动数据加载），所以**第一步先把安全网补强**。

## 2. 实现规格

### D19b-1 补强安全网（单独一个 commit，必须零差异）

`scripts/model_snapshot.cjs` 每个组合的摘要再加：

1. **完整内容的哈希**：每条曲线所有点、每个剖面的所有行、每段 single print 的 `[bottom, top]`，各算一个 SHA-1（数字先格式化成 10 位有效数字，避免浮点尾数）。D19 只比较了首尾两个点，中间点变了发现不了。
2. **页面外观**：K 线 series 的 `upColor` / `downColor` / `visible`；水印文字和颜色；图例、表格、成交量副图是否显示；当前显示的周期按钮和模板按钮；收盘倒计时是否存在。
3. **`calcLastClosedUtc`** 和 manifest 的 `values`（直接调用模板的 `manifestValues`，和 `d1_daily_png.cjs` 用同一个函数）。
4. **快照模式**：再加 7 个组合，BTC 每个模板一个默认周期，用 `snapshot=1` 打开。快照数据由新 helper `routeSyntheticSnapshot(page)` 提供：用 `rows()` 的模拟行情拼出和 `d1_build_snapshot.py` 同样格式的 `analysis/data/BTCUSDT.json`（含 30m、1h、4h、1d、1w、1M）。共 37 个组合。

`scripts/model_diff.cjs`：请求记录不参与比较，单独输出一张表：每个组合 base / head 的请求次数和各周期的 limit 总和。

### D19b-2 季度和综合拆成模板，公共部分拆成图层

- 新建 `web/analysis/layers/`，把现在 `buildAnalysis` 里的公共计算按图层拆开：`quarterBands.js`（季度 VWAP 灰带和信息行用的季度值）、`keyLevels.js`（历史关键价位选择）、`valueAreas.js`（PQ / PM / PW）、`zones.js`（供需区）、`npoc.js`（未回补 POC）。每个图层注册到 `window.OrderFlowLayers[id]`，包含：
  - `needs(ctx)`：需要哪些周期、各多少根（D19b-3 用）；
  - `build(ctx)`：原样搬过来的计算。
- 新建 `web/analysis/templates/quarter.js` 和 `combined.js`：声明自己用哪些图层，信息行和 manifest 值也搬进来。
- `main.js` 只负责调度：读模板配置，**只计算开启的图层**，合并结果，交给 primitive 画。
- `main.js` 里不再出现任何模板 id：URL 拼接和 PNG 文件名里的 `state.template==='combined'` 改成读模板配置（例如 `fileSuffix`、`keepsViewParam`）。CI 检查从“≤ 4 次”改成“0 次”。
- 目标：`main.js` ≤ 30KB。新文件按正常格式写，单行不超过 160 个字符。
- 每拆一块一个 commit，每个 commit 都零差异。

### D19b-3 按需拉数据

- 每个模板需要的数据 = 显示周期 + 开启的图层 `needs()` 的并集 + 模板自己的 `history`。`data.js` 的 `loadLive` 和 `refreshLiveBundle` 只拉这些，删掉写死的 `[周期, '1h', '30m', calc]`。
- 关闭供需区的模板不再拉 calc 周期。`calcLastClosedUtc` 在这些模板里改用**显示周期最后一根已收盘 K 线**计算。如果这会改变 `calcLastClosedUtc` 的值，在 `model_diff.cjs` 里把这个字段单独列为“允许变化”，并在回复里写出变化前后的值；其他字段仍然必须零差异。
- 快照模式不受影响（快照文件里本来就有全部周期）。
- **请求次数上限**（实时模式，一次打开页面，不含刷新）：

| 模板 | 现在 | 上限 |
|---|---|---|
| 季度 1h | 8 | 4 |
| 季度 4h | 9 | 5 |
| 滚动 VWAP 4h | 10 | 2 |
| 周度 VWAP 30m | 9 | 3 |
| 月线结构 1M | 2 | 2 |
| 月度剖面 | 9 | 2 |
| 周度剖面 | 9 | 2 |
| 综合 | 8~9 | 不变 |

  用 `model_diff.cjs` 的请求表证明。某个模板确实需要更多请求时，写进回复说明原因，不要为了达标删功能。

### D19b-4 smoke 测试按模板拆分

- `scripts/d1_smoke.cjs` 里的用例按模板拆到 `scripts/smoke/quarter.cjs`、`rvwap.cjs`、`weekly.cjs`、`monthly.cjs`、`mprofile.cjs`、`wprofile.cjs`、`combined.cjs`，以及一个放共享行为（刷新、切换币种、拖动价格轴、移动端等）的 `common.cjs`。
- 新增 `scripts/smoke/run.cjs` 依次跑所有文件，失败时报出文件名和用例名；可以用参数只跑一个模板（例如 `node scripts/smoke/run.cjs weekly`）。
- `scripts/d1_smoke.cjs` 保留成一行，调用 `run.cjs`，所以 CI 和文档里的命令不用改。
- 断言内容一条都不能少；拆分前后断言总数相同，写在回复里。
